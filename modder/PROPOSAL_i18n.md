# PROPOSAL：UI 多语言（i18n）初步设计方案

状态：**初步方案，待评审** · 2026-09-24 · 基于对现有代码的实测调研（数字均为脚本统计所得）

---

## 1. 目标与非目标

**目标**：让面板/HUD 的全部**自有文字**可按语言切换，且**不改变**现有行为与布局；新增语言只需加一个数据文件。

**非目标**：
- 不翻译**游戏自身**的文字（那是游戏的事，mod 不碰）。
- 不做排版级别的本地化（不做 RTL、不做词形变化），只做**字符串替换**。
- 不在本阶段引入字体包机制（见 §5 字体约束）。

---

## 2. 现状调研（实测）

| 项 | 结果 |
|---|---|
| 现有 i18n 机制 | **没有**（代码中无 lang/locale/翻译相关逻辑）|
| 候选可翻译字符串 | **约 162 条**：行标签 51、toast 38、绘制文本 32、详情描述 41（`@stg_detail_desc` 的 return 文本）|
| 分布 | `settingsLib.gml` 95 · `worldDrawGui.gml` 24 · `notesLib.gml` 2 · 详情描述集中在 `@stg_detail_desc`（41 条）|
| 生成位置 | `@stg_build_*`（各行标签）· `@stg_act`/`@stg_act_dir`（toast）· `@stg_hint`（底部提示）· `@stg_value`（取值列）· `@stg_status_text` · `@stg_toast` |
| 设置持久化 | mod 已有配置链：`@cfgPath = @cfgDir + "@config.ini"`，找不到则回退游戏 config ⇒ 加 `lang=` 即可 |
| 选择控件 | 已有左右箭头滚动行（`@stg_act_dir` + `@stg_row_add`）⇒ 加"语言"行成本极低 |
| 文本绘制入口 | 已统一：`@stg_text_cjk`（ASCII 走游戏字体，非 ASCII 按引擎选路）⇒ **翻译文本天然复用同一条绘制路径** |
| 换行/截断 | 已有 `@stg_wrap`（两行，含无空格长串硬断）· `@stg_fit_text` ⇒ 长语言（德语/俄语）有基础保障 |
| 原生侧能力 | 已用 `GetACP`（编码）⇒ 加区域检测可行；`file_read_text/write_text` 已在（GMS 侧可读写任意路径）|

## 3. 关键设计决策

### 3.1 查表 API：key + **英文原文作兜底**

```gml
// @lang("panel.account.name", "Name")
@lang = @lang_get(key, fallback)
```

- 调用点写 **key + 现有英文原文**，查不到就用原文 ⇒ **缺翻译永远不会把界面变空**，也允许**逐块迁移**（未迁移的代码保持原样即可）。
- 迁移完成后原文仍留在代码里，作为"最终兜底"和可读性来源（评审时一眼看懂这行要显示什么）。

### 3.2 数据文件：`lang/<code>.ini`，UTF-8

```ini
[meta]
name = 简体中文
code = zh-CN
font = cjk            ; cjk | latin  —— 声明所需字形覆盖，供启动时校验

[panel.account.name]
en = Name
zh-CN = 名称
```

- **按语言一份文件**（而不是按语言一段代码）⇒ 新语言 = 新文件，零代码改动。
- 查找顺序：`<游戏目录>/lang/<code>.ini`（用户可覆盖，UTF-8）→ mod 内置语言（转换器部署）→ 英文原文兜底。
- 当前语言存 mod 配置：`lang=zh-CN`；`lang=auto` 表示按系统区域自动选择。

### 3.3 编码：文件统一 UTF-8，**部署时按引擎转码**

| 引擎 | 字符串编码 | 方案 |
|---|---|---|
| GMS（Studio 1.4 / 2.x）| UTF-8 | 直接读 UTF-8 文件（原生 `file_read_text` 宽容解码）|
| GM8.0 / 8.1 | ANSI | **转换器在部署语言文件时转成系统代码页副本**（`lang/<code>.ansi.ini`）⇒ mod 无需在 GM8 里做转换 |

理由：这是唯一能让**同一份翻译源**同时服务三引擎、又不把编码问题推给运行期的做法；与账号文件"统一系统 ANSI"的既有决策方向一致，但这里源头保留 UTF-8（便于协作与版本管理）。

### 3.4 绘制：复用现有路径，**不改渲染层**

翻译文本一律经 `@stg_text_cjk` 输出 ⇒ ASCII 走游戏字体、CJK 走 FoxWriting/图集（GM8）或内嵌字体（GMS）。**渲染层零改动**。

### 3.5 选择界面：DISPLAY 段新增一行

```
Language      <  English  >
```

- 行为等同现有滚动行（左/右切换、立即生效、写入配置）。
- 首发提供：`English`、`简体中文`、`auto`。
- `auto` 由原生侧 `GetUserDefaultUILanguage`（新增一个导出）决定；不做也不影响主流程（默认 English）。

## 4. 字体约束（决定首发语言范围）

| 引擎 | 现有字形覆盖 | 可支持 |
|---|---|---|
| GMS | 转换器内嵌 **Microsoft YaHei** | 拉丁 + 中日韩（含假名）+ 常用符号 |
| GM8.0 | FoxWriting（可用字体文件）/ 纯 GML 图集（**GB2312 + 假名**）| 简体中文 + 日文 + 拉丁 |
| GM8.1+ | GaseousMarble 字体 | 取决于游戏字体/注入字体 |

⇒ **首发就做 `en` + `zh-CN`（+ 预留 `ja`）**；西里尔/阿拉伯/泰文等需要**字体包**，本方案只预留 `font = cjk | latin` 声明与启动校验（缺字形时回退英文并提示，而不是画成空白）。

---

## 5. 迁移路径（分阶段、可随时停）

| 阶段 | 内容 | 产出 |
|---|---|---|
| P1 | `langLib.gml`：查表 + 文件加载 + 兜底 + `@lang(key, fallback)`；英文表由**现有字面量**机械生成 | 机制可用，界面行为不变 |
| P2 | 迁移 `settingsLib.gml`（95 条：行标签 → toast → 详情描述 41 条）| 面板全可翻译 |
| P3 | 迁移 `worldDrawGui.gml` / `notesLib.gml`（HUD 文本）| HUD 全可翻译 |
| P4 | Language 行 + 配置持久化 + `auto` + 文档（含"如何新增语言"）| 用户可切换 |
| P5 | 发布 `zh-CN`（你本人校对）+ 门禁断言 | 双语言上线 |

**门禁**：新增一条断言——**面向用户的字面量必须经 `@lang`**（对已迁移文件生效，避免再次散落硬编码）。

## 6. 风险与待决问题

1. **文本变长**：德语/俄语普遍比英文长 30%~50%，现有固定列宽会挤 ⇒ 已确认 `@stg_wrap`/`@stg_fit_text` 可用，但**详情列建议改为按宽度自适应**（列入 P2）。
2. **键命名**：需要一次约定（`panel.<段>.<项>` / `toast.<动作>` / `hud.<元素>`）——建议在 P1 定稿后冻结。
3. **原文与翻译的一致性**：英文改动后译文会过期 ⇒ 建议在语言文件里记录 `sourceHash`（转换器校验，不一致时提示），是否要做请你定。
4. **换行与排版**：中日韩文本无空格，`@stg_wrap` 的硬断路径已处理；但**断行位置**对 CJK 不理想（不按词）⇒ 可接受，若要求高再单独做 CJK 断行规则。
5. **配置归属**：`lang` 存 mod 自己的 config 还是游戏 config（若游戏重写会丢）——建议 **mod 自己的 `@config.ini`** 优先，游戏 config 只读。

---

## 7. 需要你确认的三点

1. **首发语言范围**：`en + zh-CN`（+ 预留 ja）是否够？还是要一开始就把日文做完？
2. **`auto` 检测**要不要做（需加一个原生导出）？
3. **过期翻译校验**（`sourceHash`）做不做？做的话转换期就能提示"这条例文已过期"。
